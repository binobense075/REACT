# Class based component

- It's a normal JS class.
- Class based component is a class, which extends React.component and it has a render method that returns some piece of JSX.
- This will be converted to HTML and displayed on to the webpage.
- React.component is a class given by react, when we create a comonent then it will inherit some properties from it.
- React.component comes from React library.

- In class based component, the constructor will receive the props, we want to use the keyword super, inorder to access the props.
- Always use a this keyword inside class to access the props, it can access any where inside the calss uing this.'

- Whenever the new instance of the class is created , the constructor is called.

- super(props) is used in a class to pass the props to the parent class(React.Component).
- This allows this.props to be available inside your class.

## Why

- In JavaScript, when a class extends another class, we must call the super inside the child to run the constructor inside the parent.

## How react class based component is mounted/loading into the DOM? Life Cycle

- When the class load, a new instance is created, at first the constructor is called, after that render method is called.
- When the component is loaded, first the parent constructor is called, then the parent render method is called, while rendering if there is a child then the child constructor is called, then child render is called , once the child component is rendered, then the child componentDidMount is called and after that the parent componentDidMount is called.
- componenttDidMount is called once the component is mounted/loaded/rendered.

### ComponentDidMount is used to make a api call. But why it is used?

- Beacuse first we render our componet , and then we make a api call and re-render the component.
- React want to quicly render the componet, then make a api call and render the data.

- React will batch the render phase for multiple children.

- As soon as the class was loaded, the constructor was called, after constructor render happened, after that componentDidMount was called.

# componentDidMount

- componentDidMout is called once the component is mounted/loaded into the DOM.

- it has not yet finished mounting, it will go to the class based component and it will trigger its lifecycle methods

- When the parent instance created, the parent constructor is called, then render is called, it has not yet finished mounting, it will go to the child component and ut will trigger its lifecycle methods, now the child constructor is called, then child render is called, now the mounting is completed, so the child commponetDidMount is called, then the parent componentDidMount is called.

## What if we have multiple children inside one parent?

- Parent Constructor
- Parent Render
- - First Child Constructor
- - First Child Render
- - Second Child Constructor
- - Second Child Render
- <DOM UPDATION BEGINS IN SINGLE BATCH>
- - First Child ComponentDidMount
- - Second Child COmponentDidMount
- Parent ComponentDidMount

- Here React will not call the ComponentDidMount of the first child, it will just batch the render phase of these two child.
- The two child render phase will happen then commit phase will happen together.This is an optimization of react.

### There are three phases Mounting , Updating, Unmounting

- This is why React is Fast, Beacuse it has two phases, First Phase is Render Phase, Second is Commit Phase
- When the component is Mounting, first the constructor is called, then the render is called(this is the render phase), then the react updates the dom and then componentDidMount is called, that is why componentDidMount is the best place to make an api call.This is the Life cycle of Mounting cycle.This mounting cycle happens for every parent, every child, every component in react goes through these life cycle.

- In class based component, we can create the componentDidMount function as async
