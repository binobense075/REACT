# Single responsibility principle

- supoose we should have a function, class or any single identity of code, that should have a single responsibility.
- Don't do a lot of things in same component, if you have a multiple things to do in single component, break it down to different components.
- This is a good way of maintaining a code in modular fashion.

## Modularity

- Modularity means beaking down the code into different different small small modules.
- So that the code becomes more maintainable and more testable.
- Distributing the code into smaller smaller pieces and keeping it modular, makes the code testable and maintainable and reusable.
- We can reuse the component/code wherever we want.

## How it becomes testable?

- We can write test cases for seperate components.
- We test each and every small piece of code(modules).
- We can catch the bug very easily by testing a particular module.

- Keep our component as light as possible.

# Custom Hooks

- Creating our own custom hooks.
- To abstract the responsbility, extra responsibility from these components to different hook.
- Why are hooks used? Hooks are like utility functions.(It is just a utility functions).
- Creating a custom hook is not a mandatory thing. But it is a good practice, to make our code more modular, and more readble.
- Using the custom hook we can abstract the data we need into the component.

### Online/offline feature using custom hooks

- How to write a custom hook.
- First decide what is the input of the hook and what is the output of the hook.
- To check whether it is offline or online , we will use a event listener.
- There is a onlline event listener that was given by the broswer window.(browser gives access to window object and the window object has online event listener)
- It's not mandatory to put "use" before creating a custom hook, but react docs recommend to put it as best practice.
- Some react project use 'linter', and they set specific rules, if it not met we will get an error.(If we set up a linter according to react it will start throwing a error)
- If we write a custom hook, it have its own state, life cycle, use effect etc... it is written in react way not normal js function.

# How to make a large scale application perfomatic.How to make a large scale application performatic.

- Js file size increases by how many component it holds.
- How to optmize this?
- When we are developing a large scale applciation we have to break our app into smaller pieces.
- Suppose if we have a thousand components we don't need thousand files loaded into our website, that's useless.That will be a lot of works for browsers to do.
- We will make smaller bundels of these files. This process is known as Chunking(App chunking), Code splitting, Synamic bundling, lazy loading, on-demand loading, dynamic import and so many names.
- We have to make our application into smaller chunks, we have to make dynamic bundling.
- We have to do bundiling in a dynamic way.

## How to make smaller bundles and when to make smaller bundles?

- Suppose i am doing system design of makeMyTrip.
- I want to do logical seperation of bundles.That means a bundele should have a enough code for a feature in the website.And then we can split the bundels into the logical chunks.
- We want to smaller application inside our main large applciation.
- Separeate bundles for flights, hotels, trains, buses
- So that we don't put a load on a single bundle.
- So that the request to the JS file does not becomme heavy, it doesn't take a lot of time to get it into the broswer.
